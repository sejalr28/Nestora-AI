# SocietyBoard AI

AI-powered platform for a co-op housing society: water schedule, occupancy
directory, service requests, guest parking, and redevelopment tracking —
accessible via a WhatsApp bot and a React admin dashboard.

## Stack
- **Backend:** FastAPI + PostgreSQL + SQLAlchemy
- **LLM:** Ollama (Llama 3.1) by default — swappable to Claude/OpenAI/Gemini
  via one config value (`LLM_PROVIDER` in `.env`)
- **WhatsApp:** Twilio Sandbox (free) + ngrok for local webhook testing
- **Frontend:** React + Tailwind (admin dashboard)

### WhatsApp layer (Step 4)
- `api/routes/whatsapp.py` — `POST /api/v1/whatsapp/webhook`, the single endpoint Twilio calls on every incoming message
- `services/whatsapp/onboarding.py` — stateless onboarding: an unrecognized phone number gets a prompt; replying `Name, Building N, Flat#` links the number to a resident (auto-creating the flat if the committee hasn't pre-seeded it)
- `services/whatsapp/twilio_client.py` — outbound sending via Twilio's REST API, for future proactive use (not needed for the webhook itself, which replies via TwiML)
- Known residents get routed straight to the Step 3 agent; unknown numbers go through onboarding first

**Sanity-check the real Ollama agent (outside WhatsApp) on your machine:**
```bash
ollama pull llama3.1
cd backend && python scripts/verify_ollama_agent.py
```
Seeds demo data if the DB is empty and gives you an interactive chat loop
against the real agent + real local Ollama — useful before wiring up Twilio.

**Set up the Twilio Sandbox (free) + ngrok:**
```bash
# 1. In the Twilio console, go to Messaging > Try it out > WhatsApp Sandbox.
#    Note the sandbox number and the join code (e.g. "join happy-tiger").
#    From your phone's WhatsApp, message that join code to the sandbox number.

# 2. Run the backend locally (see "Run it" below), then tunnel it:
ngrok http 8000

# 3. Copy the ngrok https URL into the Twilio Sandbox settings:
#    "WHEN A MESSAGE COMES IN" -> https://<your-ngrok-id>.ngrok-free.app/api/v1/whatsapp/webhook
#    Method: POST. Save.

# 4. Message the sandbox number from WhatsApp. First message from a new
#    number gets the onboarding prompt; reply e.g. "Sejal, Building 7, 302"
#    to link your number. After that, ask about water timing, flat status,
#    or report something needing a fix.
```

**Onboarding format (V1):** a new number must reply in the exact form
`Name, Building N, Flat#` (e.g. `Sejal, Building 7, 302`) — parsed with a
regex, not the LLM, so it's deterministic and cheap to test. A natural
future improvement is letting the agent itself parse free-form onboarding
replies once the core flow is proven out.

## Run it

```bash
cd societyboard-ai
cp backend/.env.example backend/.env   # defaults work as-is for local dev
docker-compose up --build
```

Apply migrations (first time, and after pulling any new migration):
```bash
docker-compose exec backend alembic upgrade head
```

Run tests:
```bash
cd backend && pip install -r requirements.txt && pytest
```

Then check:
```bash
curl http://localhost:8000/health
# {"status":"ok","environment":"development","database":"connected","llm_provider":"ollama"}

curl -X POST http://localhost:8000/api/v1/flats \
  -H "Content-Type: application/json" \
  -d '{"building_id": 1, "flat_number": 302, "status": "unknown"}'
```

If you don't want Docker for the backend itself (only Postgres), you can also run:
```bash
docker-compose up postgres -d
cd backend && python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload
```

**Note:** `Building` rows aren't created via API (there's no POST /buildings
route on purpose — the 15 buildings are fixed, one-time seed data, not
something residents or the bot create). Seed them once via a script or
directly in the DB; a `seed.py` can be added if useful.

**Alembic + Postgres ENUM gotcha (already fixed here, worth knowing):**
autogenerated downgrades drop tables but not the custom ENUM types those
columns use, so a bare `alembic downgrade base` followed by `upgrade head`
fails with "type already exists." The migration in this repo
(`alembic/versions/..._create_core_tables.py`) has manual `sa.Enum(...).drop()`
calls added to its `downgrade()` to handle this — keep that pattern if you
add more Enum columns later.
